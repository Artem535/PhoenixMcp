= Streamable HTTP implementation plan
:toc:

> *For agentic workers:* REQUIRED SUB-SKILL: use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

*Goal:* make `DrogonTransport` a stateful MCP `2025-06-18` Streamable HTTP
server with bounded, resumable SSE and a transport-neutral outbound-message
seam.

*Architecture:* HTTP state stays in private Drogon transport files.
`McpRequestHandler` owns `ServerSession` instances and receives an opaque
logical session key through `RequestEnvelope::connection_id`. `ServerSession`
never includes Drogon or an SSE type.

*Tech stack:* C++20, Folly, Drogon, GoogleTest, CTest, CMake, `rtk`.

== Global constraints

* CMake is hand-maintained and authoritative; do not generate it from Xmake.
* Run every repository command through `rtk`; Xmake is not a release blocker.
* Keep `2025-06-18` stateful HTTP isolated from later stateless MCP revisions.
* Installed headers expose no Drogon, Crow, or SSE type.
* Replay is bounded to 1,024 events and 4 MiB per stream.
* Keep stdio and existing Drogon disconnect-cancellation tests passing.

- [ ] *Step 3: Implement POST semantics.*

Normalize headers. Without `Mcp-Session-Id`, mint a candidate ID and dispatch
`RequestEnvelope{.connection_id = candidate,
.session_lookup_mode = ITransport::SessionLookupMode::Bootstrap}`.
Commit it to the private store only after a successful initialize response and
return it in the response header. With a supplied ID, validate it in the store
before dispatch. Keep the existing per-TCP cancellation token for POST; it is
not the HTTP-session lifetime token.

- [ ] *Step 4: Implement GET, DELETE, and delivery.*

GET validates `Accept: text/event-stream` and the session ID, creates a live
Drogon stream response with `Content-Type: text/event-stream` and
`Cache-Control: no-cache`, then replays the tail selected by `Last-Event-ID`.
Encode each event as:

```text
id: <stream_id:sequence>
event: message
data: <serialized JSON-RPC>


```

On `kResyncRequired`, write `event: resync-required` and close without a
partial tail. The sink appends before writing and picks one live stream only.
DELETE removes session state, unregisters streams, and invokes
`McpRequestHandler::remove_session()`.
