= Streamable HTTP design
:toc:

== Scope

This document records issue #29: Streamable HTTP for the Drogon server
transport while PhoenixMcp supports MCP `2025-06-18`. It provides stateful
HTTP sessions, SSE streams, resumability, and a transport-neutral path for
server-initiated JSON-RPC messages. It does not add authentication, Origin
validation, client transports, or Crow parity.

Crow remains an optional compatibility backend and is explicitly deferred.
It must not silently claim Streamable HTTP support until it passes the same
transport contract tests.

== Boundaries

`DrogonTransport` owns HTTP-specific state. `ServerSession` and MCP
capabilities do not see Drogon, SSE, TCP connections, or HTTP headers.

The transport introduces an internal `HttpSessionStore`:

* `HttpSessionState` owns the logical `ServerSession`, active SSE streams,
  event journals, and last-activity time.
* `StreamState` owns one open SSE response, an opaque stream ID, its next
  sequence value, and its bounded replay journal.
* `ServerMessageSink` is the transport-neutral internal seam used by
  `ServerSession` and future progress/logging/resource capabilities to publish
  a JSON-RPC message to a logical session.

The sink selects exactly one live stream for a session. It never broadcasts a
single JSON-RPC message to multiple streams. This preserves the Streamable
HTTP multi-connection rule while allowing a client to hold multiple streams.

== HTTP lifecycle

`POST /mcp` carrying `initialize` and no `Mcp-Session-Id` creates a logical
session. On a successful initialize response, the server emits a
cryptographically random, visible-ASCII session ID in `Mcp-Session-Id`.

POST requires `Content-Type: application/json` (parameters such as a charset
are allowed); another media type returns `415 Unsupported Media Type`. A
malformed or lifecycle-invalid bootstrap returns `400 Bad Request` and does
not retain a session.

Every later `POST`, `GET`, and `DELETE` carries that header:

* a missing session ID on a request that requires one returns `400 Bad
  Request`;
* an unknown or expired ID returns `404 Not Found`;
* `DELETE` closes the logical session, cancels its active streams and work,
  and removes its event state;
* a second `DELETE`, or any later request using that ID, returns `404`.

An SSE disconnect removes only its `StreamState`; it does not close the
logical HTTP session. The session remains available until `DELETE` or idle
expiry, so a client can reconnect with `Last-Event-ID`.

== SSE and resumability

`GET /mcp` requires a valid session ID and `Accept: text/event-stream`.
`*/*` is also accepted; an incompatible media type returns `406 Not
Acceptable`. The response has `Content-Type: text/event-stream`,
`Cache-Control: no-cache`, and the current `Mcp-Session-Id`.
It opens a new `StreamState`, or resumes the stream identified by
`Last-Event-ID`.

Each delivered MCP JSON-RPC message is encoded as an SSE `message` event. Its
ID is `stream_id:sequence`: it is globally unique within the session and also
identifies the originating stream. Each stream journals at most 1,024 events
and 4 MiB of serialized payload. The journal evicts oldest events first.

On reconnect, `Last-Event-ID` must identify the resumed stream. The transport
replays exactly the events after that cursor from that stream, then keeps that
stream live. It never replays an event from another stream. If the cursor has
been evicted, the transport writes a vendor-defined SSE
`resync-required` control event and closes the stream. The client must create
or reinitialize the required state rather than silently continuing with a
gap.

== Errors, limits, and security

Malformed POST bodies return `400`. GET without an acceptable SSE media type
returns `406`. Session and journal state are bounded; deleting or expiring a
session releases all associated state.

Session IDs are generated by a cryptographically secure random source, limited
to visible ASCII, and redacted from normal logs. Request authentication and
Origin/host validation are deliberately left to issue #40, but checks are
placed before `HttpSessionStore` access so that policy can be inserted without
changing session or SSE code.

== Verification

The current CTest coverage combines private-store unit tests and the live
Drogon example integration test. It covers:

* visible-ASCII session IDs, bounded journals, replay, eviction, and
  `resync-required` decisions;
* initialize ID issuance, `400` for a missing session ID, `415` for an invalid
  POST media type, and `406` for an incompatible SSE `Accept` header;
* SSE response negotiation and heartbeat, `DELETE` cleanup, and `404` after
  deletion; and
* server-initiated SSE delivery and wire-level replay after a reconnect with
  `Last-Event-ID`; and
* TCP disconnect cancelling an in-flight POST.

The private stream-store contract additionally verifies that, with two live
streams, each server-initiated message is selected for exactly one stream.

These tests are separate from later protocol conformance tests. They prove the
transport contract before issue #30 exercises the MCP server end-to-end.
