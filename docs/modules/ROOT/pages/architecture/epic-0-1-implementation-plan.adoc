= PhoenixMcp Epic 0–1 Implementation Plan
:toc:

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the public C++ SDK layout and make a hand-maintained CMake
build the authoritative build, while retaining Xmake as a supported secondary
frontend.

**Architecture:** Public headers are installed only from
`include/phoenix_mcp`; private headers remain adjacent to their `.cc` files in
`src/phoenix_mcp`. CMake owns target topology, options, dependency resolution,
install/export rules, packaging, and CI; Xmake mirrors supported targets and is
verified by Linux smoke jobs.

**Tech Stack:** C++20, CMake 3.28+, Ninja, vcpkg manifest mode, CTest, CPack,
GoogleTest/GoogleMock, Folly, reflect-cpp, Xmake, and `rtk` for all commands.

== Global constraints

* Use `rtk` for every shell command and `rtk git` for Git inspection.
* `CMakeLists.txt` is hand-maintained; never regenerate it from Xmake.
* Use `.h` and `.cc`, lowercase `snake_case` filenames, Google include order,
  path-derived include guards, and `namespace phoenix_mcp`.
* Preserve `pxm` as a deprecated transition alias; do not remove existing
  server functionality during the foundation work.
* CMake has a floor of 3.28, uses C++20, Ninja presets, vcpkg manifest mode,
  CTest, and CPack.
* A stdio-only configuration must not require Drogon, Crow, OpenSSL, Brotli,
  c-ares, or HTTP-server dependencies.
* Public targets are `PhoenixMcp::Core`, `::Protocol`, `::Server`, `::Client`,
  `::Host`, `::TransportStdio`, `::TransportHttp`, `::TransportDrogon`,
  `::TransportCrow`, `::Telemetry`, and `::Testing`.

== File map

* Create `cmake/PhoenixMcpOptions.cmake` for all public feature options.
* Create `cmake/PhoenixMcpDependencies.cmake` for vcpkg package discovery.
* Create `cmake/PhoenixMcpWarnings.cmake` and
  `cmake/PhoenixMcpSanitizers.cmake` for compiler policy.
* Create `cmake/PhoenixMcpConfig.cmake.in` for downstream `find_package`.
* Replace `CMakeLists.txt` with the authoritative target, install, export, and
  CTest entry point.
* Create `CMakePresets.json`, `vcpkg.json`, and `VERSION`.
* Move/introduce public headers under `include/phoenix_mcp`; keep private
  headers in `src/phoenix_mcp/<component>`.
* Create mirrored test folders below `tests/phoenix_mcp`.
* Update `xmake.lua`, `src/phoenix_mcp/xmake.lua`, READMEs, `AGENTS.md`, and
  Antora architecture/build/style pages.

== Plan self-review

*Coverage:* Tasks 1 and 3 implement Epic 0 repository/API rules; Tasks 2 and
4–7 cover
the authoritative CMake build, manifest dependencies, presets, install/export,
CTest, Xmake parity, CI, and documentation required by Epic 1.

*Consistency:* Every task uses the same `phoenix_mcp` namespace, public include
root, target names, C++20/CMake 3.28 floors, and `rtk` command rule.

*Scope:* MCP Client, Streamable HTTP correctness, conformance, resources, and
prompts are intentionally excluded; they are later epics that consume this
foundation.
